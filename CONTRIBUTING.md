# Definition of Done
The acceptance criteria are met:
* Tested by hand in /docs, and in client.py if the client uses it
* Feature has been tested before being used in production
* Reviewed and approved by at least one other person
* Merged to main, and main still runs
* No keys or passwords in the code
* Feature meets acceptance criteria
* Code has been reviewed by someone else
* Comments from code review have been resolved
* No bugs remain
* Code has been integrated into a main branch
* The code should handle non-standard user input without crashing

# Coding standard 
## Naming
* Use descriptive names for variables and functions
* Use snake case (for example `this_is_snake_case`)

## PEP 8
* Use 4 space for intendation, not tabs.
* Use snake_case for variables and functions
* Use PascalCase for classes
* Keep lines relatively short (traditionally max 70 characters per line for code)
* Use blank lines to structure the code
* Put blank spaces around operators

## Docstrings
"""
This is a doc string example
"""

Doc strings can be used as needed to document what a function or a class does.

## Branch names 
* Should describe what feature the branch contains
* Prefixes like `feature/return-a-book` or `fix/search-bug` can be used

## How you review
* Read through the code changes on GitHub
* Leave comments if you have questions or change suggestions
